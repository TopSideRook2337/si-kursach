# 3 Разработка интеллектуальной системы

## 3.1 Архитектура системы

Система реализована на Python 3 в виде набора модулей (рисунок {fig:arch}); библиотека NumPy применяется только для векторных вычислений.

!fig arch | docs/figures/architecture.png | 16 | Архитектура гибридной интеллектуальной системы

Модуль model.py содержит классы предметной области и моделирование маршрутов, generator.py – генератор задач, пакет fuzzy – функции принадлежности, лингвистические переменные, базу правил и вывод Мамдани, пакет ga – кодирование, операторы, функцию приспособленности и цикл ГА, baselines.py – базовые методы для сравнения (случайное решение, «ближайший сосед», полный перебор), модули visualize.py, gui.py и main.py – графики и интерфейсы. На этапе оценки приспособленности ГА передаёт хромосому функции приспособленности, та вычисляет пять показателей плана и вызывает нечёткий вывод, а полученная оценка Q возвращается в ГА и используется при отборе родителей. Диаграмма основных классов приведена в приложении Г.

Графический интерфейс (gui.py, tkinter) содержит панель параметров задачи и ГА, кнопки «Сгенерировать», «Загрузить/Сохранить JSON», «Решить», «Стоп», «Жадный алгоритм» и вкладки с картой маршрутов, графиком сходимости и результатом нечёткого вывода; ГА работает в отдельном потоке и обновляет карту каждые десять поколений. Консольный интерфейс (main.py) предоставляет те же возможности (пример вывода – в приложении В).

## 3.2 Модель задачи и генератор исходных данных

Задача описывается классом Instance (склад, клиенты, K, Q, скорость 0,5 км/мин, смена 480 мин). Функция simulate_route моделирует движение машины с ожиданием открытия окон и учётом опозданий по формуле ({eq:tw}) и разгрузкой 10 мин; evaluate_routes вычисляет показатели плана – входы нечёткой модели.

Генератор generate_instance(n_clients, n_vehicles, seed) размещает клиентов равномерно в квадрате 40 × 40 км со складом в центре, назначает объёмы заказов 1–10 единиц и срочность (60 % обычных, 25 % повышенной срочности, 15 % срочных); вместимость подбирается так, чтобы парк был загружен на 85 %. Чтобы решение без опозданий заведомо существовало, временные окна строятся вокруг моментов прибытия в скрытом опорном плане, построенном методом заметания (клиенты делятся по полярному углу на K секторов). Опорный план системе не сообщается. Пример файла задачи приведён в приложении Б.

## 3.3 Нечёткая модель оценки качества плана

### 3.3.1 Лингвистические переменные

Входные переменные вычисляются для плана в целом, а не по маршрутам с усреднением: сбалансированность по определению характеризует соотношение маршрутов, а суммарные показатели соответствуют тому, как план оценивает ЛПР. Чёткие значения входов:

- протяжённость – отношение суммарного пробега D к пробегу D_{ref} жадного решения «ближайший сосед» на той же задаче:

!eq len | in_length

- загрузка транспорта – максимальная загрузка машины W_{k} в долях вместимости:

!eq load | in_load

- соблюдение временных окон – средняя по клиентам относительная величина опоздания, где опоздание на 60 мин и более считается полным:

!eq twin | in_timewin

- обслуживание срочных заказов – средневзвешенное время начала обслуживания срочных клиентов в долях смены (вес u_{i} − 1 равен 0 для обычных, 1 для повышенной срочности и 2 для срочных заказов):

!eq urg | in_urgency

- сбалансированность – коэффициент вариации длительностей маршрутов τ_{k} всех K машин (отношение среднеквадратического отклонения к среднему):

!eq bal | in_balance

Нормировка к эталонному решению делает протяжённость безразмерной: L = 1 – «как у жадного алгоритма», L = 0,9 – на 10 % короче. Выходная переменная «Качество решения» задана на [0; 1] пятью треугольными термами. Параметры всех функций принадлежности приведены в таблице {tab:vars}, их графики – на рисунке {fig:mf}.

!table vars | Лингвистические переменные и функции принадлежности | gen:variables

!fig mf | experiments/results/exp6_membership_all.png | 15 | Функции принадлежности лингвистических переменных

Соседние термы входных переменных образуют разбиение Руспини: склоны пересекаются на уровне 0,5, сумма степеней принадлежности равна единице. Такой выбор сделан по результатам отладки: в первой версии модели трапеции с широкими плоскими вершинами создавали «плато» – если все сработавшие правила имеют одно заключение, центр тяжести не зависит от степеней их истинности, и улучшение плана не меняет оценку. При разбиении Руспини почти любое значение принадлежит двум термам, срабатывают правила с разными заключениями, и оценка меняется плавно.

### 3.3.2 База нечётких правил

База содержит 26 правил с весовыми коэффициентами (таблица {tab:rules}; обозначения переменных: L – протяжённость, З – загрузка, T – соблюдение окон, U – обслуживание срочных заказов, B – сбалансированность, Q – качество). Её ядро – правила 1–9 – образуют полную таблицу «Протяжённость × Соблюдение временных окон»: улучшение любого из двух главных показателей на один терм повышает заключение на один терм. Поскольку термы каждой переменной покрывают весь универсум, при любых входных данных срабатывает хотя бы одно из этих правил, и база правил полна. Правила 10–26 уточняют оценку с учётом срочных заказов, загрузки и сбалансированности. Положительные правила для вспомогательных критериев сформулированы только вместе с хорошим значением пробега или окон («ЕСЛИ срочные обслужены хорошо И опозданий нет ТО …»), чтобы хорошая сбалансированность не «вытягивала» план с массовыми опозданиями. Весовые коэффициенты F < 1 назначены правилам, в которых эксперт менее уверен или которые описывают второстепенные критерии.

## 3.4 Генетический алгоритм

### 3.4.1 Кодирование решения

Решение кодируется перестановкой длины N + K − 1: гены 1, …, N – номера клиентов, гены N + 1, …, N + K − 1 – разделители маршрутов (рисунок {fig:enc}); хромосома одновременно задаёт распределение заказов по машинам и порядок объезда. Кодирование «гигантский тур с разбиением по вместимости» [@prins] отклонено: оно может потребовать больше K машин и лишает смысла переменную «Загрузка». Перестановка позволяет применять стандартный OX: его потомок – всегда корректная перестановка.

!fig enc | docs/figures/encoding.png | 16 | Кодирование плана доставки и упорядоченное скрещивание

### 3.4.2 Функция приспособленности

Приспособленность особи x равна нечёткой оценке её качества за вычетом штрафа за перегруз:

!eq fit | fitness

где Δ – суммарное превышение вместимости по всем машинам. Поскольку Q ∈ [0; 1], любой план с перегрузом получает отрицательную приспособленность и оказывается хуже любого допустимого плана; слагаемое Δ/Q сохраняет различия между недопустимыми планами, чтобы ГА мог постепенно выводить популяцию из недопустимой области. Вычисленные значения кэшируются по хромосоме: одинаковые особи, часто возникающие после элитизма, повторно не оцениваются.

### 3.4.3 Генетические операторы

Отбор родителей – турнирный с размером турнира k = 3 (для сравнения реализованы также рулеточный и ранговый отбор). Скрещивание OX выполняется с вероятностью p_{c} = 0,9 и даёт двух потомков (родители меняются ролями); реализация приведена в листинге {lst:ox}. Каждый потомок с вероятностью p_{m} подвергается одной из трёх мутаций, выбранной равновероятно:

- обмен двух случайных генов – меняет местами клиентов (возможно, из разных маршрутов) или перемещает разделитель;
- инверсия отрезка – разворачивает часть маршрута, что устраняет самопересечения (аналог улучшения 2-opt);
- перенос клиента – удаляет случайного клиента из его маршрута и вставляет в случайную позицию другого маршрута, изменяя распределение заказов.

### 3.4.4 Начальная популяция, элитизм и останов

Схема алгоритма приведена на рисунке {fig:gaflow}. Начальная популяция на 90 % состоит из случайных перестановок и на 10 % – из решений рандомизированного «ближайшего соседа» (следующий клиент выбирается случайно среди трёх ближайших). «Засев» эвристикой – распространённый приём [@prins]: без него при N = 50 все случайные особи попадают в область, где нечёткая оценка постоянна. Две лучшие особи переносятся в следующее поколение без изменений (элитизм). Алгоритм останавливается по достижении заданного числа поколений, при отсутствии улучшения в течение 120 поколений (стагнация) или по лимиту времени. Параметры по умолчанию (P = 100, p_{c} = 0,9, p_{m} = 0,2, k = 3, две элиты) выбраны по экспериментам подраздела 4.5.
