## Тема

**«Разработка гибридной интеллектуальной системы планирования маршрутов доставки на основе генетического алгоритма и нечёткой логики»**

Основа — пункт 13 перечня тем методички («Поиск оптимального пути передачи трафика с применением генетических алгоритмов»), расширенный вторым методом ИИ, потому что методичка (раздел 3.2) требует минимум два интеллектуальных подхода.

Суть гибридизации (это главная идея, она должна быть явно видна и в коде, и в записке):
**генетический алгоритм ищет решение задачи маршрутизации транспорта (распределение заказов по машинам + порядок объезда), а нечёткий вывод по алгоритму Мамдани вычисляет оценку качества маршрута, которая служит функцией приспособленности ГА.** Методы не независимы — один вызывает другой на каждой особи каждого поколения.

Никакого машинного обучения и датасетов нет. Входные задачи генерируются программно (с фиксированным seed для воспроизводимости).

## Программа

### Ограничения по реализации

- Генетический алгоритм и нечёткий вывод Мамдани пишутся **с нуля**, без skfuzzy, DEAP, pygad и подобных библиотек. Студент должен суметь объяснить каждую строку. Разрешены: numpy, matplotlib, python-docx, tkinter (стандартный), pytest.
- Код чистый, модульный, с docstring и комментариями на русском в ключевых местах. Без переусложнения.

### Постановка задачи (CVRP с временными окнами, упрощённая)

- Склад + N клиентов на плоскости (координаты), у каждого клиента: объём груза, срочность (0–1 или 1–3), временное окно.
- K машин одинаковой грузоподъёмности, скорость постоянная, все стартуют и заканчивают на складе.
- Генератор задач: `generate_instance(n_clients, n_vehicles, seed)`.
- Хранение задач в JSON, чтобы эксперименты были воспроизводимы.

### Модули (примерная структура)

```
src/
  model.py        # классы Client, Vehicle, Instance, Solution; расчёт расстояний, метрик маршрута
  generator.py    # генерация тестовых задач
  fuzzy/
    membership.py # треугольные и трапециевидные функции принадлежности
    variables.py  # лингвистические переменные и термы
    rules.py      # база правил (продукционная модель ЕСЛИ–ТО с весовыми коэффициентами)
    mamdani.py    # 6 этапов: формирование базы правил, фаззификация, агрегирование (min),
                  # активизация (min), аккумуляция (max), дефаззификация (центр тяжести)
  ga/
    encoding.py   # хромосома: перестановка клиентов + разбиение на маршруты машин
    operators.py  # турнирный отбор, упорядоченное скрещивание (OX), мутации: swap, inversion, перенос клиента между машинами
    fitness.py    # приспособленность = результат нечёткого вывода (+ штраф за жёсткие нарушения)
    engine.py     # цикл поколений, элитизм, критерии останова, журнал сходимости
  baselines.py    # жадный «ближайший сосед», случайное решение, полный перебор для малых N (≤8) для проверки
  visualize.py    # рисование маршрутов (matplotlib), график сходимости, графики функций принадлежности
  gui.py          # простое окно tkinter: параметры задачи и ГА, кнопка «Решить», карта маршрутов, лог
  main.py         # CLI-запуск
tests/            # pytest: функции принадлежности, этапы Мамдани на ручном примере, корректность операторов ГА
```

Используй разумный вариант кодирования хромосомы (например, «гигантский тур» + разбиение по вместимости, или перестановка с разделителями) — выбор зафиксируй в `DECISIONS.md` и обоснуй в записке.

### Нечёткая модель (стартовый вариант, можешь доработать)

Входные лингвистические переменные (вычисляются для решения или для каждого маршрута с последующим усреднением — выбери и обоснуй):
- **Протяжённость** (нормированная к эталону, например к решению жадного алгоритма): короткая / средняя / длинная.
- **Загрузка транспорта** (доля от вместимости): низкая / нормальная / перегрузка.
- **Соблюдение временных окон** (доля опозданий или суммарное опоздание): хорошее / удовлетворительное / плохое.
- **Обслуживание срочных заказов** (насколько рано в маршрутах стоят срочные клиенты): хорошее / среднее / плохое.
- **Сбалансированность** нагрузки между машинами: равномерная / неравномерная.

Выход: **Качество решения** [0..1]: очень низкое / низкое / среднее / высокое / очень высокое.

База правил: 20–30 правил ЕСЛИ–ТО с весовыми коэффициентами Fi, как в разделе 3.3.2 методички. Каждое правило — с кратким пояснением (методичка показывает формат «Правило — ПОЯСНЕНИЕ»).

Жёсткие ограничения (перегруз сверх вместимости) дополнительно штрафуются вне нечёткого блока, чтобы ГА не скатывался в недопустимые решения. Это тоже обосновать.

### Эксперименты (`experiments/run_experiments.py`)

Генерирует PNG-графики и CSV/таблицы, которые потом вставляются в записку:
1. Сравнение ГА+нечёткая оценка против: случайного решения, жадного «ближайшего соседа», ГА с обычной взвешенной суммой вместо нечёткого блока. На размерах N = 10, 20, 30, 50. Метрики: пробег, опоздания, перегрузы, нечёткая оценка, время.
2. Для N ≤ 8 — сравнение с полным перебором (насколько близко ГА к оптимуму).
3. Графики сходимости (лучшая и средняя приспособленность по поколениям).
4. Влияние параметров: размер популяции (20/50/100/200), вероятность мутации (0.01/0.05/0.1/0.3), тип отбора. Каждая конфигурация — несколько запусков с разными seed, среднее и разброс.
5. Карты маршрутов: начальное поколение и финальное решение на одной задаче.
6. Графики функций принадлежности всех лингвистических переменных.
7. Пример полного прохода Мамдани для одного конкретного решения: значения фаззификации, сработавшие правила и их степени, итоговое значение дефаззификации — оформить таблицей (методичка в разделе 4 требует показывать нечёткие коэффициенты и как получен вывод).

Всё должно запускаться одной командой и укладываться в несколько минут.
